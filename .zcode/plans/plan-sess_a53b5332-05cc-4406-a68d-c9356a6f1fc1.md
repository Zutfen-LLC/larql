# LARQL-GPU-B3A: CUDA Graph replay for the resident decode FFN (revised)

All 11 review points incorporated. The most consequential changes: (1) a **zero-D2D ping-pong arena** that resolves the ownership contradiction and saves the ≥25% gate; (2) a **minimal native smoke test first** to de-risk cudarc + driver behavior before the refactor; (3) **generation/layer identity** (not host pointer/len) as the primary graph key; (4) **explicit Drop ordering**; (5) **capture-aware profiling counters** with correct node-vs-submission semantics; (6) **per-backend graph mode**; (7) **strict capture mode + default instantiate flags**.

## Verified facts that shape the revised design

- **Resident-attention's final residual-add** (pipeline.rs:1955-1973, `launch_residual_add_dev(h_dev, &normed_dev/​&o_dev, ...)`) is the natural write-point for the ping-pong "B" buffer. Giving that residual an `*_into(&mut B)` form lets attention write into the stable FFN-input buffer directly — **zero D2D seed copies, zero output copies**. This is the change that makes the structural gate hold: 252 → 36 submissions, not 252 → 72 or 108.
- `CU_STREAM_CAPTURE_MODE_GLOBAL = 0` is the strictest mode and is correct for LARQL's single-threaded, single-default-stream decode contract (point 5). A forbidden sync inside capture is a defect to fix, not tolerate.
- `result::graph::instantiate(graph, flags)` with `flags = 0` (no `AUTO_FREE_ON_LAUNCH`) is correct — the FFN graph has no graph-managed allocation nodes, so the auto-free flag is unnecessary (point 5). We start with default flags.
- `note_launch` increments `profile.launches` (runtime.rs:1749). During capture, `*_into` launchers will still call `note_launch` — these represent **captured node construction**, not physical execution. The counter redesign (point 8) splits these.

## B3A-SMOKE — Minimal native graph smoke test *(FIRST, before any refactor)*

A focused RTX 3060 test in `crates/larql-compute-cuda/tests/` (or inline `#[cfg(test)]` gated by a runtime-availability check like the existing `q4km_*` tests). It:

1. Allocates a stable input `CudaSlice<f32>` and a stable output `CudaSlice<f32>` via `runtime.stream` (the exact default stream LARQL uses).
2. `stream.begin_capture(CU_STREAM_CAPTURE_MODE_GLOBAL)` → runs one existing simple kernel (e.g. `launch_activation_silu_into` or the simplest existing `_dev` launcher writing into the stable output buffer) → `stream.end_capture(flags = 0)` → asserts a `CudaGraph` is returned.
3. Seeds input with known values, `graph.launch()`, `sync`, reads back output, asserts correctness.
4. **Changes the input buffer contents** (re-upload into the same stable buffer), `graph.launch()` again, asserts the new output reflects the changed input (proving stable-pointer replay picks up buffer mutations).
5. Drops the graph, then the buffers — asserts clean teardown (no driver error logged).
6. **Repeats after a runtime/reset cycle**: new arena, new graph, rebuild, replay, teardown — proving repeated create→replay→reset→rebuild works on the installed RTX 3060 driver/runtime (610.43.03 / NVRTC 12.4.127).
7. Optionally calls `graph.upload()` before first launch and measures whether it avoids first-launch setup cost.

This validates capture on the LARQL stream, cudarc event-tracking during capture, instantiation/launch, repeated replay with mutated buffers, stable-pointer behavior, and teardown — all before committing to the larger B3A-2…B3A-7 refactor. **If the smoke test reveals an incompatibility, stop and report rather than proceeding.**

## B3A-2 — Graphable resident FFN contract + generation/layer identity *(point 6)*

New module `crates/larql-compute-cuda/src/ffn_graph.rs`:

- `struct GraphGenerationId(u64)` — opaque generation token.
- `struct ResidentFfnPlan` — the immutable FFN properties: `hidden, inter, stored_cols, gate_fmt, up_fmt, down_fmt, ffn_type, activation, has_post_norms, pre/post-ffn norm presence, eps, norm_offset, residual_multiplier`. Built via `ResidentFfnPlan::from_layer(...)` which **calls** the existing `supported_resident_ffn_triple` / `down_stored_cols` / `native_activation_worthwhile` gates (single source of truth — no duplication).
- **Cache identity = `(generation, layer_index, ResidentFfnPlan)`**. NOT host pointer/len. Each layer captures different device weight pointers (its own gate/up/down), so no cross-layer deduplication is attempted even when shapes/activation match (point 6). Host `(ptr,len)` values remain a **diagnostic assertion** (a changed weight address within the same generation is a bug) but are not the primary ABA defense — generation invalidation is.
- Host-runnable tests: equal plan → equal; different quant/activation/dims → distinct.

## B3A-3 — Generation-scoped resident decode arena — the explicit ownership model *(point 2 — the linchpin)*

**Ownership model (chosen, documented):**

```
struct ResidentDecodeArena {
    // Two stable hidden-state ping-pong buffers, [hidden] each.
    hidden_a: CudaSlice<f32>,
    hidden_b: CudaSlice<f32>,
    generation: GraphGenerationId,
}
```

**Data flow per eligible layer (zero D2D copies):**
```
stable hidden A  →  resident attention reads A, writes stable post-attn B
                                              (attn residual_add_into(&mut B))
                 →  FFN graph reads B, writes stable hidden A
                                    (graph's residual_add_into(&mut A))
                 →  next layer repeats (reads the just-written A)
```

**Addressing each required statement:**
- **Who owns every graph-referenced buffer**: the `ResidentDecodeArena` owns `hidden_a`/`hidden_b` (graph I/O) at a fixed device address for the arena's lifetime. The per-layer `ResidentFfnGraph` entry owns its internal scratch (`normed_input, gate_out, up_out, act, down_out, post_norm_out`) and `Arc<CudaSlice<u8>>` clones of gate/up/down weights + graph-owned norm-weight buffers.
- **How the next layer accesses the prior output**: by index — even layers read `hidden_b`/write `hidden_a`, odd layers read `hidden_a`/write `hidden_b` (or tracked by a flip flag). The graph reads from a fixed slot; the slot's *contents* change each token, but the **address is stable** (verified by B3A-SMOKE step 4). No `CudaSlice` is moved out of the arena.
- **Whether any D2D copy is required**: **zero** on the steady-state path. The attention block already produces a residual output; we only redirect it to write into stable B via `launch_residual_add_into(&mut B)` instead of allocating fresh. The FFN graph writes into stable A. The input embedding at token boundary is one HtoD (already exists today via `ensure_device`); no per-layer D2D.
- **How no borrowed reference escapes a graph-cache lock**: the decode loop holds the graph entry by `Arc` (cloned out of the `Mutex<HashMap>` under the lock, lock dropped immediately), OR — if a `CudaSlice` reference is needed — passes `&arena.hidden_b` into `graph.launch()` replay which reads the buffer's device pointer at launch time (no handle escapes). The arena itself is borrowed `&` for the duration of one layer's graph replay; the lock is never held across the launch.
- **How buffer addresses remain stable across every replay**: the arena is allocated **once per generation** (at first decode token, or lazily); `hidden_a`/`hidden_b` `CudaSlice` handles are never moved/reallocated until the generation resets. The graph captured against their `cu_device_ptr` remains valid for every replay in that generation.

This resolves the contradiction in v1: the graph never owns the hidden buffer and `DecodeHiddenState` never moves it — the **arena** owns it, and both attention and FFN write into it by stable address.

## B3A-4 — Allocation-free into-buffer launch primitives

Add `*_into` variants in `backend/runtime.rs` taking `&mut CudaSlice<f32>` (and `&CudaSlice<f32>` for device-resident norm weights) instead of `alloc_zeros`:

- **FFN chain (7)**: `launch_rms_norm_into` (norm weight now a `&CudaSlice<f32>` device arg, eliminating the per-call `clone_htod` at runtime.rs:2322), `launch_q4k_matvec_into`, `launch_q6k_matvec_into`, `launch_geglu_silu_into` / `launch_geglu_gelu_tanh_into` / `launch_activation_silu_into` / `launch_activation_gelu_tanh_into` (via refactored `launch_elementwise_binary_into` / `launch_elementwise_unary_into`), `launch_residual_add_into`.
- **Attention residual** (the ping-pong write-point): `launch_residual_add_into(&self, base, other, out: &mut CudaSlice<f32>, n, res_mult)` — used by the resident-attention block (pipeline.rs:1966-1972) to write into stable B. This does **not** graph attention or change its semantics; it only redirects the final residual output.
- **Drift prevention**: each existing `*_dev` is refactored to validate + `alloc_zeros` + delegate to `*_into`. The non-graph resident FFN path stays the live correctness oracle and exercises the identical kernel-arg layout.

## B3A-5 — Build & replay one FFN graph per eligible layer *(point 1 — token 1 launches)*

`ResidentFfnGraph::build(runtime, plan, weights, input_slot: &CudaSlice, output_slot: &mut CudaSlice, scratch) -> Result<Self,_>`:
1. Allocate internal scratch + upload norm weights (one-time).
2. Resolve gate/up/down `Arc<CudaSlice<u8>>` from `weight_cache` (warm from prefill; upload-then-capture if cold).
3. `begin_capture(GLOBAL)` → 7 `*_into` launches writing into scratch + `output_slot` → `end_capture(flags=0)` → `Option<CudaGraph>`.
4. `graph.upload()` to pre-stage first launch.

**Token 1 contract (point 1)**: after build, the graph **must be launched for token 1** — capture/instantiation do not produce the FFN result. `graph.launch()` runs the chain.

**Counter semantics (point 1)** — exact:
```
graph_builds        += num_layers              (on token 1)
graph_submissions   += num_layers * num_tokens (every token incl. token 1)
warm_replays        += num_layers * (num_tokens - 1)  (token 2+, reserved name)
```
Token 1's launches count toward `graph_submissions`, not `warm_replays`.

**Replay contract**: physical kernels execute in the same mathematical order (byte-identical `*_into` launches into stable buffers). Output feeds the next layer via the arena's stable slot (no host boundary).

**Fallback (point 10)**: any build/replay `Err` → existing resident FFN **device** chain for that layer (the non-graph `host_ffn_block_device_resident` path, which now uses the same `*_into` primitives but with fresh allocations). NOT to CPU, NOT re-running attention, NOT double-appending KV, NOT reading hidden to host. The graph path is a strict alternate execution of the same FFN block on the same post-attn state. Attention path and host K/V mirror **untouched**.

## B3A-6 — Explicit graph destruction order + generation-scoped lifecycle *(points 6, 7)*

```
struct ResidentFfnGraph {
    graph: Option<CudaGraph>,           // Option so Drop can take() in order
    scratch: Option<ResidentFfnGraphScratch>,
    weights: Option<RetainedWeights>,   // Arc<CudaSlice<u8>> gate/up/down + norm
}
impl Drop for ResidentFfnGraph {
    fn drop(&mut self) {
        // Explicit order (point 7):
        // 1. destroy executable graph (CudaGraph::drop → execDestroy + destroy)
        self.graph.take();
        // 2. (captured graph is owned inside CudaGraph — destroyed with it)
        // 3. release graph scratch + norm buffers
        self.scratch.take();
        // 4. release retained weight-buffer handles
        self.weights.take();
        // 5. stream/context destroyed later by CudaRuntime
    }
}
```

**Cache** (point 6):
```
struct ResidentFfnGraphCache {
    generation: GraphGenerationId,
    layers: Vec<Option<ResidentFfnGraph>>,
}
```
- Reset path (extended `reset_kv_cache_native`, point 6 order): **increment/replace generation → destroy all graph executables (drop `layers`) → release scratch + retained weights → then flush weight cache**.
- `DecodeHiddenState::Device` no longer carries graph output ownership — the arena owns the hidden buffers; `DecodeHiddenState` for the graph path holds only an arena index/flag (`DeviceArena { slot: HiddenSlot }`) plus a fallback `Device { dev: CudaSlice }` for the non-graph path. The final end-of-token readback reads from the arena's active slot.

**Stress test (point 7)**: repeated create→replay→reset→rebuild→drop (not single reset).

## B3A-7 — Per-backend graph mode + capture-aware counters *(points 8, 9)*

**Graph mode (point 9)** — resolved at backend construction, stored on the backend:
```
struct CudaBackendConfig { graph_mode: GraphMode }  // Auto | Disabled
```
- `LARQL_CUDA_GRAPHS=0` → Disabled; `=1` → Auto (forced on); unset → Auto (default-on only after B3A-11 gate; until then Auto = Disabled unless the env opt-in is set).
- Hot path reads `backend.config.graph_mode`, never process-global env.
- Tests construct graph-enabled/disabled backends in one process without `set_var` or order dependence (point 9).

**Profiling counters (point 8)** — capture-aware, distinct:
```
direct_kernel_submissions       // note_launch on non-captured _dev launches
graph_builds                    // one per build()
graph_submissions               // one per graph.launch() (incl. token 1)
captured_kernel_nodes           // += node_count during build (the 7 *_into calls)
logical_graph_kernel_executions // += node_count per graph.launch()
graph_failures                  // build Err
graph_fallbacks                 // replay Err → resident device chain
d2d_submissions                 // any D2D copy (expected 0 on the happy path; counted honestly if any occur)
```
- During capture: `captured_kernel_nodes += 7`; the `*_into` launchers **do not** increment `direct_kernel_submissions` when in a capture context (a capture flag on the runtime suppresses it).
- During launch: `graph_submissions += 1`, `logical_graph_kernel_executions += 7`.
- The existing `launches`/`htod`/`dtoh`/`syncs` PROFILE fields are preserved where their meaning is accurate; the new fields are added alongside and clearly versioned in the JSON + docs. The old `launches` becomes `direct_kernel_submissions` semantically (renamed in the snapshot, with a doc note).

Diagnostic surface (under `LARQL_GPU_DIAG`): `cuda resident-FFN graph: builds=N, submissions=S, replays=R, failures=F, fallbacks=FB, replay_rate=P%, captured_nodes=CN, logical_execs=LE, d2d=D`.

## B3A-11 — Revised performance decision gate *(point 11)*
B3A complete only when ALL hold:
- B3A-SMOKE passes on RTX 3060.
- Stable graph I/O ownership explicitly implemented + documented (ping-pong arena).
- Token 1 launches the newly built graph.
- `graph_builds ≤ num_layers` per generation; later tokens rebuild zero.
- Graph replay parity `max_abs < 1e-3`.
- Resident-KV + resident-hidden remain 100% active.
- Reset/rebuild/fallback/teardown + repeated lifecycle tests pass.
- All D2D copies counted in submission accounting.
- Total host CUDA submissions/token fall **≥25%** on real Q4_K_M.
- Transfer + sync counts do not regress.
- Same-day median decode improves **≥1%** before graph mode becomes default-on.
- Graph construction cost amortizes within ~64-token generation.
- No benchmark claim excludes construction cost without also reporting it separately.
- RTX 3060 validation final; no RTX 3090 rerun.

Positive-but-<1% → opt-in + honest doc. Build-not-amortized-in-64 → opt-in + flag cache design. Regression → disable + recommend B4.
